## 1. 处理流程

```text
公开题干 + 已整理问题 + 方法知识 + 工具说明
                         ↓
              临时交接档案与字段映射
                         ↓
        输入 / 过程 / 目标 / 核验证据分层
                         ↓
           问题理解、方法选择、工具使用
                         ↓
          模型回答 → 在线检查 → 工具执行
                         ↓
             独立核验、运行记录与报告
```

模型生成回答，求解器计算，Harness组织请求、检查接口、有限反馈、调度工具并记录。**格式合格不等于答案正确**，因此还需独立核验。

| 任务二要求 | 实现 | 边界 |
|---|---|---|
| 训练要素提取与统一表达 | 配置来源字段、类型、必需性和映射，记录来源及补充条件 | 接收已整理材料；目前以直接映射为主 |
| 输入、过程与目标分层 | 分开保存input、process、target、evidence，请求采用白名单 | 参考答案不能整体进入请求 |
| 面向学习目标配置模板 | 同一题生成四种视图，归属三类模板 | 不是四种模板类别 |
| 复用与实例化验证 | 跨案例实例化、导出往返检查、错误注入及真实运行 | 不代表完整项目场景已覆盖 |

## 3. 三类模板

| 类别 | 视图 | 模型输入 | 输出 |
|---|---|---|---|
| 问题理解 | understanding | 题干、补充条件、实体次序、空字段约定 | 结构化问题和缺失项 |
| 方法选择 | method | 已核验问题、求解要求、候选知识卡 | 方法编号、条件及说明 |
| 工具使用 | call | 问题参数、已选方法、接口说明 | 工具名称及arguments |
| 工具使用 | result | 问题、实际工具返回、状态定义 | 方案、目标值、终止状态与后续处理 |

原有四道完整题各四个视图，共16个。v1.3新增题是三个完整案例各四个视图、一个不完整案例三个视图，共15个。独立测试使用已准备输入，后续视图不必等待模型读题成功，便于定位各层错误。历史额外串联测试使用上一步实际输出，失败即停止，不换入参考答案；本轮新题未额外测试串联。

工人分配例子：统一记录保存工人、任务及费用矩阵；方法模板允许专用指派或MILP；调用模板要求矩阵与实体顺序不变；返回模板核对实际状态、分配方案和成本。专用指派使用SciPy的修改版Jonker–Volgenant实现，不笼统称为匈牙利算法。

## 4. 代码结构与作用

按职责保留代码目录和已有命令；详细说明从首页拆出，见[文档导航](docs/README.md)。

```text
task2/expansion.py     本轮新增四题与双模型入口（python -m task2.expansion）
run_templates.py      原有四题模板入口，保留兼容
task2/                模板、执行环路、求解工具及报告
configs/task2/        字段映射、模板定义和方法知识卡
demo/                 复用的基础模块，以及保留的旧流程
data/                 题干、结构化问题、独立参考
tests/                自动化测试
reports/              可提交的实测摘要
docs/                 详细讲解与输入阅读副本
scripts/              辅助导出脚本
outputs/              本机完整记录，被Git忽略
```

| 模块 | 关键作用 |
|---|---|
| `run_templates.py` | 调度instantiate、validate、run、report、probe，选择案例与后端 |
| `task2/core.py` | archive整理档案；instantiate分角色；messages只取白名单；导出两种JSONL |
| `task2/workflow.py` | 准备实例和真实求解返回，检查隔离与复用，运行串联及人工故障测试 |
| `task2/runtime.py` | run_view执行环路；check_online在线检查；grade独立评分 |
| `task2/handoff.py`、`contracts.py` | 区分可接收的部分问题与可执行问题；绑定模板版本、输出字段和检查器 |
| `task2/evidence.py`、`diagnostics.py` | 记录四题关键字段的原文或补充约定位置；输出字段级独立核验明细 |
| `task2/boundaries.py` | 六个明确标注的开发边界视图及本地实测入口 |
| `task2/tools.py` | 校验调用，在限时子进程执行SciPy求解，不执行模型生成代码 |
| `demo/backend.py`、`model_worker.py` | 在独立环境加载本地0.5B并生成回答 |
| `demo/ollama_backend.py` | 通过HTTP访问已有Ollama服务，不下载模型 |
| `demo/validation.py`、`evaluation.py` | 格式、类型和维度检查；原约束、目标重算及参考对齐 |
| `task2/report.py`、`compare.py` | 从真实记录生成单次报告及模型对比 |

```text
core.messages：生成受控请求
             ↓
backend.generate：模型回答
             ↓
runtime.check_online：仅使用可见信息检查
   失败 → 反馈具体错误，最多修正2次
   通过 → call视图执行tools.solve；其他视图结束
             ↓
runtime.grade：隐藏参考独立判分，不把答案反馈给模型
```

`mappings.json`规定字段映射，`templates.json`规定输入和指令，`methods.json`提供方法知识。增加算法还需更新适用规则、工具注册及测试，不是只增加知识卡。

`demo/`不是纯历史目录，任务二仍复用其中的模块。根目录旧入口`run_demo.py`、`run_fault_checks.py`和`check_environment.py`保留兼容，不计入本轮主流程。

v1.3新增`task2/expansion.py`负责读取新题交接、独立枚举/矛盾证书核验、冻结实例、双模型预算控制和公开摘要投影。它复用`core → workflow → runtime → tools`，没有另写一套模板。`data/task2_v13/catalog.json`保存题干与来源，`handoffs.json`保存4题参考问题；后者不能整体发送给模型。

### 按真实调用顺序读代码

```text
expansion.main：解析命令、拒绝覆盖旧目录
  → load_records：读catalog与handoffs，核对独立证书
      → core.archive：接收部分/完整问题，统一字段
  → workflow.prepare：完整题执行参考工具，生成适用视图
      → core.instantiate：按学习目标分input/process/target/evidence
      → export_views：输出模板示例，再回读检查
  → workflow.validate：检查接口、隔离、配置与复用
  → expansion.run_models：顺序运行本地与服务器模型，共享时间预算
      → runtime.run_view：请求 → 解析 → 在线检查 → 合法工具执行/反馈
          → runtime.grade：尝试结束后再用隐藏参考判分
  → public_summary：核对冻结输入哈希，只导出允许公开的字段
```

`--validate-only`在validate之后结束，不调用模型，但prepare仍会真实执行参考求解。独立视图中的方法和调用输入来自整理好的交接，不需要前一视图成功；历史`workflow.run_chain`才传递模型实际中间产物，本轮新题没有额外串联实验。

### 三轮模板迭代

| 阶段 | 主要问题 | 处理方式 | 仍不能宣称什么 |
|---|---|---|---|
| v1.1：建立骨架 | 早期演示偏描述到求解，缺少不同学习目标的组织 | 临时交接、三类四视图、白名单、在线/离线分离、固定工具 | 求解成功不等于全部模板要求完成 |
| v1.2：补齐约定与边界 | 真实缺字段难进入、字段错误难定位、方法知识表达不足 | 部分问题检查、缺失策略、字段证据、方法步骤要素、六个边界开发视图 | 有测试仍可能存在规则误判；开放解释未自动认证 |
| v1.3：修复并扩题 | 单位脱离约束误判、缺字段提示冲突、原题覆盖有限 | 约束级单位匹配、统一省略规则、类型反例、12候选/4核验、同输入双模型 | 14B仍误删parameters；12题不是全部已验证，更不是12种问题类别 |

这里按三个模板版本归纳，不把每次对话当作独立发布。v1.1之前的五题求解演示保留为旧流程；历史成绩不重算为当前版本成绩。

## 5. 实测结果

### v1.3修复与新题同输入对照

本轮修复的是模板和检查器，不是直接改模型答案：

- 单位与同一条归一化约束对应检查；变量边界使用数量单位，预算使用金额单位。等价重排、正比例缩放和受支持的边界表达可通过，错误单位不通过。不支持通用单位换算、一般冗余约束消除。
- 缺字段统一为省略字段并列出完整路径，不再同时要求保持全部键。若出现“标记缺失却填写空矩阵”，反馈指出具体字段；只允许模型修正，不静默删除输出。
- 显式整数/连续变量要求保留；连续变量反例能通过理解核验，但不因此宣称已注册完整连续LP方法和工具链。

工程测试与模型成绩分开统计：**207项自动化测试通过；新题33项实例/隔离/导出/复用检查通过**。人工故障、模拟超时与假模型修复测试均不算真实模型成功。参考材料由枚举或简单矛盾证明核验，仍待人工复核。

两模型的15份首轮请求逐条一致，参考返回只生成一次；后续反馈由实际回答决定。原始结果位于本地`outputs/task2_v13_comparison`，公开字段摘要见[本轮结果](reports/task2-v13-results.json)。共用60分钟预算，实际视图耗时合计约6.7分钟。没有服务阻塞或未完成视图。

**具体失败与修复：**

- 0.5B的问题理解出现类别、实体、字段遗漏等错误；玻璃调用把两条`<=`改成`=`，图书预算调用把预算`<=`改成`=`，被拦截，未执行错误工具调用。返回解读出现非法next_action或状态混淆。
- 0.5B维修题的方法选择首轮未返回规定的待补字段，第二轮正确返回`missing_fields`，这是本轮唯一真实反馈修复，不是修改提示后重跑成功。
- 14B维修题的理解首轮仍保留`cost_matrix: []`；反馈后删除了整个parameters，把已知tasks也丢掉。三轮均未通过。模板冲突已修复，但模型的局部字段编辑能力仍未通过这一测试，不能自动删除空矩阵后冒充模型成功。
- 14B对同题的方法选择、调用构造均正确请求补充。没有费用，不执行求解器，也不存在返回解读成绩。其余三道完整题的12个视图全部首轮通过。

- 打印机理解：仍把明确约定的整数变量写成连续变量，属于约定遵循错误。

## 6. 快速运行

在仓库根目录使用Python 3.12准备环境：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pytest -q
```

准备模板不调用大模型，但会真实求解，以准备返回解读材料：

新增4题的独立工程检查（15视图、3次参考工具执行，不运行模型）：

```powershell
.\.venv\Scripts\python.exe -m task2.expansion --directory outputs/task2_v13_check_new --validate-only
```

同一批新题的双模型实测；两模型使用相同冻结输入，共用60分钟请求预算。必须使用新目录。服务失败或超时会停止该后端余下请求，未执行与答错分开保存：

```powershell
.\.venv\Scripts\python.exe -m task2.expansion --directory outputs/task2_v13_new --models local ollama --minutes 60
```

只运行本地模型可用`--models local`。可选`--public-summary reports/task2-v13-new-results.json`生成字段白名单摘要。60分钟后不发起新请求，已发请求仍受自身超时限制；不保证服务端同步取消。下列旧入口仍可运行原有四题，但会生成当前v1.3模板：

```powershell
.\.venv\Scripts\python.exe run_templates.py instantiate --directory outputs/task2_new
.\.venv\Scripts\python.exe run_templates.py validate --directory outputs/task2_new
```

本轮本地0.5B和边界实测入口如下。需先按后文配置本地模型环境，目录应使用尚未保存结果的新名称。

```powershell
.\.venv\Scripts\python.exe run_templates.py run --directory outputs/task2_new --backend local --chain
.\.venv\Scripts\python.exe -m task2.boundaries --directory outputs/task2_boundary_new
```

边界命令加`--validate-only`仅生成并检查模板，不调用模型；实测应另选新目录，不覆盖该记录。旧v1.1/v1.2实例不能用于新版run，请重新instantiate；原有记录仍可阅读，不会被迁移或改分。

服务器模式要求已有Ollama服务及调用权限。通过SSH隧道转发至本地11435时：

```powershell
$env:DEMO_OLLAMA_URL = 'http://127.0.0.1:11435'
.\.venv\Scripts\python.exe run_templates.py probe --backend ollama
.\.venv\Scripts\python.exe run_templates.py run --directory outputs/task2_new --backend ollama --model qwen2.5:14b --chain
```

本地模式另需PyTorch、Transformers、CUDA模型环境与已有权重。配置`DEMO_MODEL_PYTHON`、`DEMO_MODEL_PATH`后，使用`run --backend local`。不自动下载权重。两种后端不要复用已有results.json的目录。

`--case assignment --form call`只测单个视图。默认首轮加至多两次修正；退出码0表示运行完成，不代表答对。复跑请使用新目录，历史结果不覆盖。
