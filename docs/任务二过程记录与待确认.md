# 任务二过程记录与待确认

## 本轮做了什么

在旧Demo外新增独立入口、配置与代码，没有删除历史结果。统一档案包含题干、结构化问题、方法知识、算法骨架、工具契约和参考资料；每个案例按输入、过程、目标、证据组织，形成三类模板、四种视图。调用构造由真实本地Qwen完成，只有校验通过才执行注册工具。

主用案例为工人分配、打印机、面包房、广告预算。配送只留在旧Demo及回归中。没有下载受限数据、引入其他模型、微调、调用付费API或提交推送GitHub。

完整结果以每个目录的results.json为准，报告从同一文件生成。工程检查通过不等于模型能力通过；开放文字的依据仍待人工复核。

## 已发现并处理

1. **主线容易偏向任务一。** 旧流程让模型读题后直接求解，新流程改为先整理临时档案再配置不同学习目标。问题理解只是其中一个视图，不再阻塞所有独立测试。
2. **参数包装容易被误当作模型工具使用。** 新调用视图由Qwen生成tool_name和arguments，程序只检查和执行，不用参考调用替代失败输出。
3. **同一档案容易泄漏答案。** 模型请求只从input白名单构造；target、process、evidence和实例文件名不进入消息。测试改变隐藏目标后，在线消息和反馈保持不变。
4. **Schema文本干扰小模型。** v1.0中模型误抄字段范围或输出类型描述；v1.1把模型阅读说明简化，完整Schema保留在校验端。此举有改善，但没有解决全部失败。
5. **一个问题可以有多种合法方法。** 工人分配同时接受专用指派与MILP，不要求唯一首选。三道整数线性题筛选后只有MILP候选，这部分成功不能被称作自由算法选择能力。
6. **无解与失败必须区分。** 广告题真实求解和独立费用下界均说明无解。模板允许正确解释无解，不通过改约束强行制造方案。
7. **结果状态容易混淆。** 检查最优、无解、达到时限、外部超时、无界与工具异常。MILP若在限制内有可行但未证最优的解，保留候选并明确未证最优；模拟测试覆盖这些分支，不伪装成真实超时实验。

## 仍存在的问题

- **结构化输出仍不稳定。** v1.1的问题理解4题均未通过，出现空实体、漏missing_information、目标字段对象化等；工人分配串联在问题理解阶段停止，下游未执行。
- **工具使用只部分通过。** 打印机调用首轮成功，实际结果5050通过独立核验；另外3个调用视图未通过接口检查，不能声称已普遍掌握工具调用。
- **返回解读仍有状态错误。** 广告无解视图通过；其他3题存在空方案或最优性表述错误。需要先分析指令理解与输出表示，再决定后续优化。
- **反馈有效性没有得到正例支持。** 允许两次修正并留下记录，但本轮没有修复成功。人工注入测试能证明机制按规则运行，不能证明Qwen会改对。
- **开放文本尚未自动验证。** 方法依据和解释即使结构通过，也可能说得不充分。报告将这部分与数值、条件编号核验分开，统一标待人工复核。
- **语义与单位检查有边界。** 结构对齐不是通用数学等价证明，单位标签不是量纲换算证明。逐字段原文依据仍需人复核。
